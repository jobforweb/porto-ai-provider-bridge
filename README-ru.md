# Porto AI Provider Bridge

WordPress-плагин для темы **Porto**, который переключает встроенный AI-генератор контента с OpenAI на внешний OpenAI-совместимый провайдер. Плагин проверен и работает с провайдером **Ollama**. Работоспособность подтверждена на официальных зарегистрированных версиях шаблона WordPress **PORTO** (Автор: P-THEMES) **v.7.10.0 - v.7.10.2**.

**Цель плагина** — подключить встроенный AI-генератор темы Porto к бесплатным открытым языковым моделям через OpenAI-совместимые провайдеры, развернутые на собственном сервере. Такой подход позволяет отказаться от расходов на платные облачные AI-API и повысить приватность: промпты, черновики и контент обрабатываются в вашей инфраструктуре и не передаются сторонним коммерческим сервисам.

Решение позволяет продолжать пользоваться родным интерфейсом Porto (генерация описаний товаров, excerpt, meta title/meta description, outline и т.д.), но вместо платного OpenAI API запросы уходят на локальный или контрольный сервер с моделью `qwen3.6:27b-coding`.

Автор: **LVI**. Сайт: https://jobforweb.ru/

## Что дает плагин

- Подмена модели OpenAI на модель провайдера через нативный фильтр Porto `porto_ai_model`.
- Подстановка заглушки API-ключа, потому что Porto требует заполненное поле ключа даже при работе с внешним провайдером.
- Адаптация тела запроса под провайдера:
  - принудительное отключение потоковой передачи (`stream: false`);
  - отключение внутренних «рассуждений» модели (`think: false`);
  - удаление параметров, специфичных для OpenAI;
  - добавление инструкции в system prompt, чтобы модель сразу возвращала чистый текст.
- Перенаправление HTTP-запроса с адреса OpenAI на адрес провайдера из настроек плагина.
- Увеличение таймаутов: PHP-запрос — 120 секунд, браузерный AJAX — 120 секунд.
- Все используемые параметры вынесены в админку: от модели и URL до префикса OpenAI, AJAX-экшена и списка экранов.
- Сохранение нативных значений Porto для `max_tokens` и `temperature`, если поля переопределения оставлены пустыми.
- Работа без редактирования родительской темы `porto` и без переноса AI-кода в дочернюю тему.

## Требования

- WordPress с активной темой **Porto** и активной дочерней темой **Porto Child**.
- Официальная зарегистрированная версия шаблона Porto (Автор: P-THEMES) v.7.10.0 - v.7.10.2 с поддержкой AI-функционала и фильтров `porto_ai_*`.
- Работающий OpenAI-совместимый провайдер с эндпоинтом:

```text
http://HOST:PORT/v1/chat/completions
```

- Модель, загруженная на сервере провайдера. В конфигурации по умолчанию используется:

```text
qwen3.6:27b-coding
```

- Сетевая доступность сервера WordPress к серверу провайдера.
- Заполненное поле API-ключа в настройках AI темы Porto. Фактически это может быть любая непустая строка, например `sk-ollama-local`.
- PHP 7.4 или новее.

## Установка

1. Скопируйте всю папку плагина, включая вложенную папку `admin`, в каталог плагинов WordPress:

```text
wp-content/plugins/porto-ai-provider-bridge/
```

   Внутри должны находиться `porto-ai-provider-bridge.php` и `admin/papb-admin.php`.

2. Если в дочерней теме ранее использовалась старая связка, удалите из `wp-content/themes/porto-child/functions.php` блок, начинающийся с комментария:

```php
// Связка Ollama + Porto
```

   Стандартный блок загрузки CSS дочерней темы оставьте как есть. Это важно, чтобы не дублировать хуки `porto_ai_*`.

3. Активируйте плагин **Porto AI Provider Bridge** в разделе «Плагины».

4. Откройте настройки темы:

```text
Porto → Theme Options → AI
```

   и укажите любой непустой API-ключ, например:

```text
sk-ollama-local
```

5. Откройте страницу плагина:

```text
Настройки → Porto AI Bridge
```

   Либо используйте ссылку «Настройки» в списке плагинов рядом с названием плагина.

6. Проверьте поля, сохраните изменения и проверьте генерацию через стандартный интерфейс Porto: запись, страница или товар WooCommerce → блок Porto AI → Generate.

> Важно: не редактируйте родительскую тему `porto`. Плагин подключается через стандартные хуки и не меняет файлы темы.

## Настройки в админке

Все параметры находятся на странице **Настройки → Porto AI Bridge**. Админка вынесена в отдельный файл `admin/papb-admin.php`, но для пользователя ничего не меняется: это та же страница настроек со ссылкой в списке плагинов.

Таблица настроек состоит из двух столбцов:

- слева — само поле ввода;
- справа — соответствие в Porto и значение по умолчанию.

| Поле | Значение по умолчанию | Соответствие в PORTO |
|---|---:|---|
| Модель | `qwen3.6:27b-coding` | Фильтр `porto_ai_model` → `PORTO_AI_MODEL` |
| URL провайдера | `http://127.0.0.1:11434/v1/` | `pre_http_request` → `PORTO_OLLAMA_URL` |
| Префикс адреса OpenAI | `https://api.openai.com/v1/` | `pre_http_request` → `PORTO_PAPB_OPENAI_PREFIX` |
| Хост запроса OpenAI | `api.openai.com` | `pre_http_request` → `PORTO_PAPB_OPENAI_HOST` |
| Заглушка API-ключа | `sk-ollama-local` | Фильтр `porto_ai_openai_key` → `PORTO_OLLAMA_API_KEY_STUB` |
| Таймаут PHP, сек | `120` | `pre_http_request` → `$args['timeout']` → `PORTO_OLLAMA_TIMEOUT` |
| Таймаут браузера, мс | `120000` | JS `$.ajax` → `PORTO_JS_TIMEOUT` |
| Отключать рассуждения | Включено | `porto_ai_request_body` → `think: false` → `PORTO_OLLAMA_DISABLE_THINKING` |
| Принудительно `stream: false` | Включено | `porto_ai_request_body` → `stream` → `PORTO_PAPB_FORCE_STREAM` |
| Дополнительная инструкция | `CRITICAL: Do NOT use internal reasoning or thinking process. Start writing the final text IMMEDIATELY. Return ONLY pure text.` | `porto_ai_request_body` → `messages[system].content` → `PORTO_OLLAMA_SYSTEM_HINT` |
| Лимит токенов | Не задано; Porto: content 2048, excerpt 64, meta description 265, outline 2048 | `porto_ai_request_body` → `max_tokens` → `PORTO_OLLAMA_MAX_TOKENS_OVERRIDE` |
| Температура | Не задано; Porto: content 0.9, excerpt 0.1, meta description 0.3 | `porto_ai_request_body` → `temperature` → `PORTO_OLLAMA_TEMPERATURE_OVERRIDE` |
| Удаляемые параметры OpenAI | `response_format, logprobs, top_logprobs, n, seed` | `porto_ai_request_body` → `unset()` → `PORTO_PAPB_UNSET_PARAMS` |
| AJAX-экшен Porto AI | `porto_ai_generate` | `admin-ajax.php` → `action` → `PORTO_PAPB_AJAX_ACTION` |
| Экраны админки | `post,page` | `admin_footer` → `$screen->base` → `PORTO_PAPB_ADMIN_SCREENS` |
| Отключать проверку SSL | Включено (`sslverify = false`) | `pre_http_request` → `$args['sslverify']` → `PORTO_OLLAMA_SSLVERIFY` |

### Приоритет констант

Если соответствующая константа уже определена, например в `wp-config.php`, она имеет приоритет над значением из админки. Это оставлено для совместимости со старой схемой настройки:


### Значения Porto, которые сохраняются по умолчанию

Пока поля `Лимит токенов` и `Температура` пусты, традиционные параметры Porto остаются без изменений:

| Параметр | Тип контента | Значение Porto |
|---|---|---:|
| `max_tokens` | content | 2048 |
| `max_tokens` | excerpt | 64 |
| `max_tokens` | meta description | 265 |
| `max_tokens` | outline | 2048 |
| `temperature` | content | 0.9 |
| `temperature` | excerpt | 0.1 |
| `temperature` | meta description | 0.3 |

Точные значения зависят от версии темы Porto; после обновления темы имеет смысл повторно проверить генерацию.

## Подготовка провайдера

Сейчас плагин проверен с провайдером Ollama. В будущем предполагается поддержка и других OpenAI-совместимых серверов (llama.cpp, LM Studio и др.), но их особенности API пока не проверены.

На сервере Ollama выполните:

```bash
ollama pull qwen3.6:27b-coding
```

Если Ollama запущена на другой машине, убедитесь, что она слушает не только `127.0.0.1`. Например:

```bash
OLLAMA_HOST=0.0.0.0:11222 ollama serve
```

Далее проверьте доступность API с того сервера, где работает WordPress:

```bash
curl -sS -X POST "http://HOST:PORT/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.6:27b-coding",
    "stream": false,
    "think": false,
    "messages": [
      {"role": "user", "content": "Скажи ОК"}
    ]
  }'
```

В ответе должен быть JSON с полем `choices[0].message.content`.

## Как работает плагин

1. Пользователь нажимает Generate в AI-блоке Porto.
2. Porto отправляет AJAX-запрос с `action`, заданным в поле «AJAX-экшен Porto AI».
3. Фильтры `porto_ai_model`, `porto_ai_openai_key` и `porto_ai_request_body` подготавливают запрос по настройкам плагина.
4. Хук `pre_http_request` ищет запрос по полю «Хост запроса OpenAI» и заменяет «Префикс адреса OpenAI» на адрес провайдера.
5. Ответ провайдера возвращается в Porto в том же формате, в котором его ожидает тема.
6. JS-перехватчик увеличивает таймаут AJAX только на экранах из поля «Экраны админки» и только для нужного `action`.

Другие внешние HTTP-запросы WordPress не затрагиваются.

## Проверка работоспособности

1. В терминале провайдера при нажатии Generate должна появляться строка `POST /v1/chat/completions`.
2. В браузере: `F12 → Network → Fetch/XHR` — запрос `admin-ajax.php` с нужным `action` должен завершаться статусом `200`.
3. В ответе должен появиться сгенерированный текст, вставленный в поле Porto.
4. Для коротких промптов ответ приходит быстро; для описаний примерно на 10 предложений генерация стабильна на тестовом продакшн-хостинге.

## Известные ограничения

- Генерация примерно до **10 предложений** работает стабильно.
- Запросы на **20 и более предложений** могут завершаться ошибкой `Request time is out`. Это ограничение инфраструктуры: веб-сервер/хостинг может обрывать длинные PHP-запросы, даже если в настройках плагина заданы увеличенные таймауты.
- Если длинные тексты нужны регулярно, используйте один из подходов:
  - увеличить на хостинге `fastcgi_read_timeout`, `proxy_read_timeout` и `max_execution_time`;
  - генерировать текст частями: введение, основная часть, заключение;
  - использовать более быструю модель провайдера;
  - при необходимости реализовать фоновую очередь генерации отдельно.
- Текущая версия не содержит асинхронной очереди: запрос остается синхронным, чтобы сохранить родную логику Porto и не ломать интерфейс темы.
- Поддержка других провайдеров, кроме Ollama, пока не реализована: название плагина отражает направление развития, но проверен только OpenAI-совместимый API Ollama.
- Отключение флага «Принудительно `stream: false`» может привести к потоку SSE, который Porto не умеет разбирать.

## Диагностика типовых ошибок

| Симптом | Что проверить |
|---|---|
| `Request Failed` сразу после нажатия | Поля «URL провайдера», «Хост запроса OpenAI», «Префикс адреса OpenAI», порт, модель и доступность эндпоинта. |
| `cURL error 28` / таймаут | Поля «Таймаут PHP, сек» и «Таймаут браузера, мс», лимиты хостинга, скорость модели. |
| `No content was generated` | Включен ли флаг «Отключать рассуждения»; заполнена ли «Дополнительная инструкция»; возвращает ли модель непустой `content`. |
| Текст обрывается на середине слова | Увеличьте поле «Лимит токенов», но помните про таймауты. |
| 10 предложений работает, 20 — нет | Ограничение хостинга или браузера; уменьшите объем за один запрос либо измените настройки сервера. |
| Porto пишет об ошибке ключа | В настройках Porto AI поле API Key должно быть заполнено любым непустым значением; проверьте «Заглушку API-ключа». |
| Настройки плагина не применяются | Проверьте, не задана ли соответствующая константа в `wp-config.php`, и обновите страницу после сохранения. |
| JS-таймаут не применяется | Поля «AJAX-экшен Porto AI» и «Экраны админки»; текущий экран должен быть `post` или `page`. |

## Безопасность

- Провайдер по умолчанию может не требовать авторизации. Не публикуйте его порт в открытом интернете без фаервола, VPN или защищенного туннеля.
- Проверка SSL по умолчанию отключена (`sslverify = false`), чтобы плагин работал с локальными и туннельными адресами. Используйте только доверенные каналы. При необходимости включите проверку в настройках плагина.
- После обновления Porto или провайдера обязательно повторно проверяйте генерацию: тема может изменить имена хуков, AJAX-экшен или формат запроса.
